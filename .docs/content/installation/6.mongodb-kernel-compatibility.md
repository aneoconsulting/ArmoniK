# MongoDB and recent Linux kernels

The default MongoDB image (`percona/percona-server-mongodb`, tag set in `versions.tfvars.json`) does not start on some recent Linux kernels. This page explains how to detect the issue and which image to use instead.

This is a known upstream issue in MongoDB, not an ArmoniK bug. This page reflects the situation as of November 2026.

## Symptom

The MongoDB pod (`mongodb-db-ps-rs0-0` on a local deployment) is in `CrashLoopBackOff`. The `mongod` container exits with code 1 right after starting, and its logs are empty. The deployment then times out waiting for MongoDB:

```text
MongoNetworkError: getaddrinfo ENOTFOUND mongodb-db-ps-rs0.armonik.svc.cluster.local
Timed out waiting for MongoDB to be ready
```

Running `mongod --version` with the same image prints the actual reason:

```bash
kubectl -n armonik run mongod-version --rm -it --restart=Never \
  --image=percona/percona-server-mongodb:<tag> --command -- mongod --version
```

```text
{"s":"F","c":"CONTROL","id":12257600,"ctx":"main","msg":"MongoDB cannot start: Linux kernel versions 6.19 and newer has a known incompatibility with this version of MongoDB. See https://jira.mongodb.org/browse/SERVER-121912 for more information."}
```

## Cause

Linux kernels from 6.19 up to 7.0.13 changed the behavior of `rseq`, which breaks the memory allocator bundled with MongoDB 8.0. Kernels 7.0.14 and newer restore the previous behavior and are not affected ([SERVER-121912](https://jira.mongodb.org/browse/SERVER-121912), [SERVER-125742](https://jira.mongodb.org/browse/SERVER-125742)).

To avoid crashes, MongoDB 8.0.21 added a startup check. With the default image, `mongod` refuses to start when the kernel release string (`uname -r`) is from 6.19 up to 7.0.13. Ubuntu keeps the release string at `7.0.0` for its whole 7.0 kernel series, even when it is based on upstream 7.0.14, so MongoDB refuses to start on these kernels too ([SERVER-136848](https://jira.mongodb.org/browse/SERVER-136848), not fixed yet).

This affects Ubuntu 26.04 hosts, the Ubuntu 24.04 and 26.04 GitHub-hosted runners, and any host whose `uname -r` is from 6.19 up to 7.0.13.

## Check your kernel

```bash
uname -r
cat /proc/version_signature   # Ubuntu only: the last field is the upstream kernel version
```

- `uname -r` from 6.19 up to 7.0.13 (for example `7.0.0-...` on Ubuntu 26.04): the default image does not start. Use one of the alternatives below.
- Otherwise (for example `6.8.0-...` or a WSL2 `6.6...` kernel): the default image works, nothing to do.

## Alternatives

| Image | Starts on these kernels | Known security fixes | Notes |
|---|---|---|---|
| `percona/percona-server-mongodb:7.0.45-24` | Yes | Up to date as of 2026-11-06 | **Recommended.** MongoDB 7.0 is supported until August 31, 2027 ([lifecycles](https://www.mongodb.com/legal/support-policy/lifecycles)). |
| `percona/percona-server-mongodb:8.0.20-8` | Yes | **Missing many fixes**, including critical ones | Last 8.0 image without the startup check. Do not use it on an upstream kernel from 6.19 up to 7.0.13, see below. |

### MongoDB 7.0 (recommended)

MongoDB 7.0 does not include the startup check, and its allocator is not affected. Percona Server for MongoDB 7.0.45-24 includes all the security fixes released for 7.0 so far ([release notes](https://docs.percona.com/percona-server-for-mongodb/7.0/release_notes/index.html)). It is the image used by the ArmoniK CI.

Data written by MongoDB 8.0 cannot be opened by MongoDB 7.0: "Binary downgrades are not supported for MongoDB Community Edition" ([Downgrade 8.0 to 7.0](https://www.mongodb.com/docs/manual/release-notes/8.0-downgrade/)). Use 7.0 for new deployments. To move an existing 8.0 deployment, back up the data with `mongodump`, deploy with 7.0 on empty storage, and restore with `mongorestore`.

### MongoDB 8.0.20

Percona Server for MongoDB 8.0.20-8 is the last 8.0 image without the startup check. It lacks the security fixes released in 8.0.21-9 and later, including several critical and unauthenticated vulnerabilities (see the [Percona Server for MongoDB 8.0 release notes](https://docs.percona.com/percona-server-for-mongodb/8.0/release_notes/index.html)).

On upstream kernels from 6.19 up to 7.0.13, MongoDB 8.0.0 to 8.0.20 can crash after about 60 seconds, with a risk of data corruption ([SERVER-125742](https://jira.mongodb.org/browse/SERVER-125742)). Only use this image if the upstream kernel version (the last field of `/proc/version_signature` on Ubuntu) is outside that range.

## Override the MongoDB image

Set the tag in the `mongodb` block of your `parameters.tfvars` (example for the localhost deployment). Keep the other settings of that block, as the whole block is replaced:

```terraform
mongodb = {
  cluster = {
    replicas = 1
    tag      = "7.0.45-24"
  }
  persistence = {}
}
```

Alternatively, change the default tag of `percona/percona-server-mongodb` in the `image_tags` section of `versions.tfvars.json`. See [Default images](5.default-images.md) for how defaults are chosen.

Go back to the default 8.0 image once a Percona Server for MongoDB release fixes [SERVER-136848](https://jira.mongodb.org/browse/SERVER-136848).
